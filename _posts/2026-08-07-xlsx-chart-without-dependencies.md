사내 통계 플랫폼의 AI 챗에 리포트 내보내기를 붙이면서 "엑셀로 뽑아줘" 요청에 CSV를 내려주게 만들었다.
UTF-8 BOM을 붙여 한글도 안 깨지고 더블클릭하면 엑셀에서 열리니 기능적으로는 문제가 없었다.
그런데 "엑셀로 뽑아줘"라고 말한 사람이 기대하는 건 `.csv`가 아니라 `.xlsx`다.
게다가 요구사항이 하나 더 붙었다 — 표만 말고 차트도 넣어 달라.

## 라이브러리 선택지가 없었다

엑셀 생성 라이브러리를 붙이는 게 정석이지만 두 가지가 걸렸다.
하나는 의존성 추가가 팀원들의 로컬 빌드를 `npm install` 전까지 깨뜨린다는 것, 다른 하나는 서버리스 번들이 커진다는 것.
그리고 결정적으로, **널리 쓰이는 무료 엑셀 라이브러리 중에 차트 삽입을 지원하는 게 없었다.**
차트를 넣으려면 결국 OOXML을 직접 써야 했다.

필요한 기능을 적어보니 생각보다 좁았다. 시트 하나, 헤더 굵게, 열 너비, 천단위 숫자 서식, 그리고 차트 하나.
xlsx는 결국 XML 몇 개를 묶은 zip이라, 이 범위면 직접 만드는 게 합리적이었다.

```
[Content_Types].xml        파트 목록
_rels/.rels                루트 관계
xl/workbook.xml            시트 목록
xl/worksheets/sheet1.xml   실제 데이터
xl/styles.xml              폰트·숫자 서식
xl/charts/chart1.xml       차트 정의
xl/drawings/drawing1.xml   차트를 시트 어디에 놓을지
```

zip은 무압축(STORE)으로 만들었다. 파일이 수 KB라 압축 이득이 없고, CRC32와 헤더만 직접 쓰면 되니 구현이 단순해진다.
표만 있는 파일은 6개 파트에 5.6KB, 차트를 넣으면 10개 파트에 12.9KB가 나왔다.

## 축은 있는데 막대가 없다

표만 있는 버전은 한 번에 통과했다. 파이썬 `openpyxl`로 열어서 zip 무결성, 한글 시트명, 헤더 굵게,
숫자 서식(`#,##0`), XML 이스케이프까지 확인하고 배포했다.

문제는 차트였다. 파일은 정상적으로 열렸고, `openpyxl`도 차트를 인식했다(`charts: 1`).
그런데 실제로 렌더링해 보니 **제목·축·눈금·범례는 다 그려지는데 막대만 없었다.** 빈 도화지에 축만 있는 상태.

XML은 well-formed였고 스키마상 빠진 것도 없어 보였다. 그래서 눈으로 비교하는 대신
**정답 파일을 만들어 파트 단위로 이분 탐색**하기로 했다. `openpyxl`로 같은 데이터의 차트 파일을 만들고,
내 패키지와 정답 패키지 사이에서 파트를 하나씩 바꿔치기한 조합 8개를 생성한 뒤,
렌더링 결과에서 시리즈 색 픽셀이 검출되는지를 자동으로 판정했다.

```python
# 조합별로 파트 하나만 교체해 굽고, 렌더 결과에 시리즈 색이 있는지 픽셀로 판정
for out_name, swap in cases.items():
    with zipfile.ZipFile(out_name + '.xlsx', 'w', zipfile.ZIP_STORED) as out:
        for name in ref.namelist():
            data = mine.read(name) if name in swap else ref.read(name)
            out.writestr(name, data)
```

결과가 깔끔하게 갈렸다.

| 교체한 파트 | 막대 렌더 |
|---|---|
| workbook.xml | 정상 |
| styles.xml | 정상 |
| [Content_Types].xml | 정상 |
| **관계 파일(.rels)** | **막대 사라짐** |

범인은 차트 XML이 아니라 **관계 파일이었다.** 정답 파일의 관계에는 테마 파트(`theme1.xml`)가 들어 있었고,
내 최소 패키지에는 테마가 아예 없었다. 차트 시리즈에 색을 명시하지 않으면 뷰어는 테마의 accent 색을 찾아가는데,
테마가 없으니 시리즈를 무색으로 그려버린 것이다. 축과 범례는 테마와 무관하니 멀쩡히 그려졌고,
그래서 "차트 XML이 잘못됐나" 쪽만 계속 뒤지게 만든 증상이었다.

## 해결

테마 파일을 통째로 넣는 방법도 있었지만, 시리즈마다 색을 명시하는 쪽을 택했다.
패키지가 가벼워지고 브랜드 컬러를 그대로 쓸 수 있다.

```ts
const spPr = forLine
  ? `<c:spPr><a:ln w="28575"><a:solidFill><a:srgbClr val="${color}"/></a:solidFill></a:ln></c:spPr>`
  : `<c:spPr><a:solidFill><a:srgbClr val="${color}"/></a:solidFill></c:spPr>`;
```

같은 맥락의 함정이 하나 더 있었다. 차트 시리즈를 셀 참조(`Sheet!$E$2:$E$8`)로만 지정하면
엑셀은 열 때 재계산해서 그리지만, **재계산하지 않는 뷰어(문서 미리보기·일부 모바일 뷰어)는 빈 차트를 보여준다.**
참조와 함께 실제 값 캐시(`numCache`/`strCache`)를 동봉해야 어디서든 동일하게 그려진다.

검증도 두 단계로 나눴다. 구조는 `openpyxl`로(zip 무결성·파트 파싱·스타일),
실제 그림은 헤드리스 오피스로 PDF 변환해 픽셀로 확인했다. **"파일이 열린다"와 "차트가 보인다"는 다른 검증이다.**

| 항목 | 처음 | 최종 |
|---|---|---|
| 응답 형식 | CSV 1종 | xlsx(서식·차트) + CSV 병행 |
| 추가 의존성 | — | 0개 |
| 구현 | — | 약 400줄, 단일 파일 |
| 검증 | 육안 | 구조 자동 검증 + 렌더 픽셀 판정 |

## 배운 것

- 포맷을 직접 만들 때 **범위를 좁게 자르면 난이도가 급격히 떨어진다.** 시트 1개·차트 1개로 한정하니
  OOXML 최소 패키지 7개 파트로 끝났다. 다중 시트·피벗·조건부 서식이 필요해지는 순간이 라이브러리로 넘어갈 시점이다.
- **증상이 나타난 파트와 원인이 있는 파트는 다를 수 있다.** 막대가 안 보인다고 차트 XML만 파면
  관계 파일에 있는 원인을 영원히 못 찾는다. 눈으로 비교하기 어려우면 정답 파일을 만들어 이분 탐색하는 게 빠르다.
- **기본값을 외부에서 상속받는 구조는 최소 패키지에서 깨진다.** 테마 색 상속이 그랬다.
  의존을 줄일 거면 상속받던 값도 같이 명시해야 한다.
- 파일 산출물은 **"열린다"까지 확인하고 끝내면 안 된다.** 구조 검증과 렌더 검증은 잡아내는 결함이 다르다.
